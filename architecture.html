Deep Dive
Every module explained: what it does, what it exports, and how data flows through it.
⚙
Agent Core
pyoz/agent.py
The brain of PyOz. Manages the agentic loop: sends user messages to the LLM, executes tool calls the LLM requests, feeds results back, and repeats until the LLM returns a final text answer. Builds the system prompt with platform-specific instructions, codebase context, and tool selection guide. Handles context window management by summarizing old messages.
  • chat()
  • _execute_tool()
  • _build_system_prompt()
  • _manage_context()
  • initialize()
  • save_session()
  • reindex()

LLM Providers
pyoz/providers/
Abstract provider interface with three implementations. Each provider translates between PyOz's internal message format and the API's native format. Handles tool schema conversion, streaming SSE parsing, token counting, and retry logic with exponential backoff. The factory in cli.py picks the right provider from CLI args.
  • BaseLLMProvider
  • ClaudeProvider
  • OpenAIProvider
  • OllamaProvider
  • ToolCall
  • LLMResponse
  • StreamEvent
⚡
Tool Registry
pyoz/tools/registry.py
Central registry of all 24 tool definitions with JSON schemas for function calling. Each entry defines name, description, parameter types, and required fields. Converts to Claude format (input_schema) or OpenAI format (function definitions) on demand. Descriptions are platform-aware — run_command says "PowerShell" on Windows.
  • TOOL_DEFINITIONS[]
  • get_tool_definitions_claude()
  • get_tool_definitions_openai()

AST Indexer
pyoz/indexer/ast_indexer.py
Parses source files to extract classes, methods, functions, fields, imports, and dependencies. Provides the LLM with structured codebase context so it understands the project before making changes. Uses tree-sitter when available, falls back to regex patterns. Supports Python, Java, Go, Rust, JS, TS, Kotlin, C#.

Cross-platform foundation that everything else builds on. Detects the OS, discovers PowerShell, maps 40+ Unix commands to PowerShell equivalents, normalizes file paths, and provides platform-specific blocked command patterns. Every tool and the system prompt adapt behavior based on these flags.

Data Flow
How a Request is Processed
A complete trace of what happens when the user types a message like "refactor this function".
1
User Input
InputManager.get_input() captures the message with readline history and autocomplete. If it starts with /, it's routed to the slash command handler instead.
2
Context Assembly
Agent.chat() appends the message to conversation history. _build_system_prompt() combines: role definition + tool selection guide + platform instructions (PowerShell on Windows) + workspace rules (PYOZ.md) + AST codebase summary.
3
LLM API Call
Provider.chat(messages, tools, system_prompt) sends the request to Claude, OpenAI, or Ollama. Tool definitions are converted to the provider's native format. Returns an LLMResponse with text and/or tool_calls.
4
Tool Execution Loop
If the LLM returned tool_calls, _execute_tool() dispatches each one to its implementation. Results are formatted per provider spec and appended to messages. The LLM is called again. This repeats up to 50 tool calls per turn.
5
Side Effects
File writes and edits trigger auto_commit() (git) and reindex_file() (AST). The on_tool_call callback displays each tool execution in the terminal with icons and formatted output.
6
Response & Persist
The final text response is rendered as markdown via Rich. Token counts and cost are displayed. SessionManager.save() persists the full conversation to ~/.pyoz/sessions/ so work is never lost.
Design
Architecture Patterns
The key design decisions that keep the codebase maintainable and extensible.
Strategy Pattern
pyoz/providers/base.py
Three LLM providers implement the same BaseLLMProvider interface. The agent works identically regardless of which provider is active. Swapping from Claude to Ollama changes zero agent code.
Dispatcher Pattern
Agent._execute_tool()
A single method routes all 24 tool calls to their implementations by name. Adding a new tool requires: one function, one registry entry, one elif branch.
Registry Pattern
pyoz/tools/registry.py
Tool schemas are defined once in a central list. Conversion to Claude or OpenAI format happens automatically. No schema duplication across providers.
Factory Pattern
cli._create_provider()
A single factory function creates the right provider from CLI args. Encapsulates API key validation, model defaults, and import logic per provider.
Observer Pattern
Agent callbacks
The agent emits events via callbacks (on_tool_call, on_diff, on_stream_token). The CLI subscribes to display them. The agent has zero knowledge of Rich or the terminal.
Platform Abstraction
pyoz/platform.py
All platform-specific logic is isolated in one module. Tools import IS_WINDOWS and adapt behavior. The LLM's system prompt automatically switches to PowerShell mode on Windows.
Context Window Mgmt
Agent._manage_context()
Old messages are summarized to a single prefix when the conversation grows long. Prevents context overflow while preserving essential history. Transparent to the user.
Auto-Commit Guard
Agent._execute_tool()
Every file write/edit auto-commits to git. This creates an undo stack (/undo reverts the last commit) and makes all agent actions auditable through git log.
